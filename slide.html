AI phân tích nhu cầu → gọi tool tìm khách sạn → trả lời bằng dữ liệu thật.
Kết quả: Top 3 khách sạn phù hợp nhất, có lý do đề xuất rõ ràng.
1 · Problem

Khách du lịch tự túc khó chọn nơi lưu trú phù hợp

Quá nhiều lựa chọnUser phải xem nhiều nền tảng như Booking, Agoda, Traveloka, Google và tự so sánh hàng chục khách sạn.
Không biết cái nào phù hợpCùng một mức giá nhưng mỗi khách sạn phù hợp với một nhóm khách khác nhau: cặp đôi, gia đình, nghỉ dưỡng hoặc tiết kiệm.
Thông tin nhập chưa đủUser thường chỉ nói “Tôi muốn đi Phú Quốc” nên AI dễ gợi ý sai nếu không hỏi lại.
Hệ quả Tốn thời gian tìm kiếm, khó đưa ra quyết định, dễ chọn khách sạn vượt ngân sách hoặc không đúng nhu cầu.
2 · Insight

Người dùng không thiếu thông tin — họ thiếu hỗ trợ ra quyết định

Các nền tảng hiện tại cung cấp rất nhiều danh sách khách sạn, nhưng người dùng vẫn phải tự đọc review, so sánh giá, tiện ích, vị trí và tự đoán lựa chọn nào phù hợp nhất với mình.

1
Nhiều khách sạn
Thông tin phân tán trên nhiều nền tảng
→
2
User tự phân tích
Đọc review, lọc giá, so sánh tiện ích
→
3
Khó quyết định
Không chắc đâu là lựa chọn tốt nhất
3 · Solution

AI Travel Concierge Bot hỗ trợ quá trình chọn khách sạn

AI không thay user đặt phòng. AI đóng vai trò trợ lý hỗ trợ ra quyết định trước khi user chọn khách sạn cuối cùng.

Understand

Hiểu điểm đến, ngân sách, số người, mục đích chuyến đi và sở thích lưu trú.

Ask Again

Hỏi thêm khi user thiếu thông tin quan trọng như ngân sách, số người hoặc phong cách du lịch.

Match

Tìm khách sạn phù hợp từ dữ liệu có sẵn, lọc theo giá, khu vực, tiện ích và loại khách hàng.

Recommend

Đề xuất Top 3 khách sạn, loại phòng, tiện ích nổi bật và lý do vì sao phù hợp.

7 · Frontend Flow

Người dùng gửi tin nhắn như thế nào?

Frontend không chỉ gửi câu hỏi. Nó gửi cả trạng thái hành trình hiện tại để AI hiểu bối cảnh người dùng đang chọn gì trên UI.

tripĐiểm đến, ngân sách, số người, sở thích.
messagesLịch sử hội thoại gần nhất.
matchedHotelsDanh sách khách sạn phù hợp đang hiển thị.
POST /api/chat { message: "câu hỏi của user", trip: { điểm đến, ngân sách, sở thích }, demoCase: "happy", history: [5-6 tin nhắn gần nhất] }
8 · Backend AI Flow

Backend xử lý AI theo 2 lần gọi

1
Chuẩn bị Context
System prompt + history + trạng thái UI + tool schema.
→
2
AI quyết định
Có cần gọi fetch_matching_hotels hay không?
→
3
Tool xử lý
Lọc dữ liệu thật, chấm điểm, lấy Top 3.
→
4
AI trả lời
Viết tư vấn tự nhiên dựa trên kết quả tool.
Điểm quan trọng AI không được tự bịa khách sạn. Dữ liệu khách sạn phải đi qua tool hoặc fallback logic từ server.
9 · Tool Calling

Hai chế độ xử lý để tránh AI “ảo tưởng”

Model Tool-Call Mode AI hiểu rằng cần dữ liệu khách sạn, tự gọi tool fetch_matching_hotels với arguments đã phân tích.
Server Fallback Mode Nếu AI không gọi tool, backend tự parse câu hỏi và ép chạy logic lọc khách sạn để vẫn có dữ liệu thật.
if (AI gọi tool) { mode = "model-tool-call" args = AI.arguments hotels = fetchMatchingHotelsFromDb(args) } else { mode = "server-fallback" args = buildToolArgsFromMessage(userMessage) hotels = fetchMatchingHotelsFromDb(args) }
10 · Core Logic

Core lọc và chấm điểm khách sạn

Input

Nhận các tiêu chí: mục đích chuyến đi, mức ngân sách, khu vực, yêu cầu chính.

Parse DB

Đọc danh sách khách sạn từ data_hotel.py và chuyển thành mảng object để xử lý.

Scoring

So khớp keyword, giá, khu vực, tiện ích, sở thích; cộng điểm match_score.

Top 3

Sắp xếp điểm từ cao xuống thấp và chọn 3 khách sạn phù hợp nhất.
